# 微信英语 Bot 管理器

当前版本：1.1.0，用量整合与图标界面版。双击 `微信英语Bot管理器-用量整合版.exe` 使用。首次运行会在程序旁解压运行环境，并创建 `data` 管理配置目录。以后直接双击同一个程序即可。

升级时，把新 EXE 放到原管理器旁边，与原 `data` 文件夹同级，继续使用同一份管理列表。不要覆盖或删除 `data`，也不要把测试目录当成正式数据。原程序可以保留备份。关闭旧管理器窗口通常只是隐藏到托盘；同一目录不允许两个管理器同时运行。

## Bot 数量与账号

- 顶部显示总数、运行中数量和待扫码数量。
- “新增 Bot”创建独立数据目录、答题工作目录和端口。选中后点击“启动”，扫码并在手机确认。
- 同时运行上限默认 3，可在界面调整为 1–20。这个数字是管理上限，不是硬件承载能力保证；多个 Bot 共用本机 Codex 登录的额度。
- 支持批量启动/停止、改名、启用/停用、移除/恢复。移除只从列表归档，账号和用量不会删除。
- 每个 Bot 只响应扫码绑定账号，群聊关闭。需要多个独立身份时，请分别扫码绑定。

## 原有两个 Bot

首次在当前电脑运行会识别原有两个项目，保留各自的登录、用量和图片目录。旧版仍运行时标记为“旧版运行”，这不等于已验证微信连通。

要统一管理，选中并点击“接管旧版”。程序先备份旧启动任务，再停止相应旧进程与旧自启动，然后以封装的新引擎启动。只有选中的项目受影响。停止状态的旧版可直接启动。

1.1.0 已修复 Windows PowerShell 5.1 读取无 BOM 中文脚本导致的解析错误。执行脚本与内嵌源码统一输出 UTF-8 BOM；JSON 与输出也明确使用 UTF-8。接管只匹配精确的旧启动脚本，类似名称目录、备份任务不属于接管目标；多动作任务需要人工核对。

每次接管有独立操作编号和备份，放在该 Bot 的 `.runtime/handoff-backups/<操作编号>`。失败时先确认本次新实例停止，再恢复同一次操作保存的旧任务状态。恢复不会自动重建已删除或已修改的任务，也不会重启没有计划任务的手工进程。若显示“接管待确认”，自动启动和重复接管会暂停；请保留 `handoff-actions.log` 和备份，核实状态后处理，不要删除保护记录后反复点击。

接管脚本执行期间管理器等待真实结果，不会在旧脚本仍修改任务时报告超时失败并允许重试。切换用量页面不影响等待。界面更新本身不会自动执行接管。

## 日常使用

- “扫码与状态”显示新二维码；需要配对数字时，可直接填写手机显示的数字。
- “重新扫码”先停止当前任务，将旧账号与上下文移动到本地 `login-backups` 备份，再显示新二维码。
- 发送图片后用 `/回答` 表示上传完成；`/新题` 清除上一题与未提交图片，`/追问 内容` 继续讨论。
- 默认 `gpt-5.6-luna`，中等推理。保留图片识别、上下文轮次清理、用量记录和人民币成本估算功能。
- “答题规则”打开当前实际采用的 gaokao-english 文件夹。本机共享技能优先，每次回答读取当前文件；没有共享技能时使用随程序附带的快照。
- 顶部“用量统计”在程序内展示统计；选中账号后点“查看用量”，会切换到该 Bot 的统计。无需浏览器，Bot 停止时也可读取已保存记录。
- 用量页支持全部或单个 Bot、今天/近 7 天/近 30 天/全部已保存，以及包含已移除 Bot。展示请求次数、输入/缓存/输出/总 Token、图片、耗时、美元费用和人民币估算。
- 每 15 秒读取本地统计文件，不调用模型、不增加模型额度消耗。人民币使用所选 Bot 中最新的有效缓存汇率，显示获取时间与过期提示；运行中的 Bot 每小时尝试联网更新汇率。无有效汇率时显示美元，人民币显示“—”。
- 费用沿用记录中的既有定价结果；旧 Luna 记录缺少费用时按既有配置（输入 $0.20、缓存输入 $0.02、输出 $1.20 / 百万 Token）补算，这不是对当前官方价格的核验。未知模型不自动套用 Luna 单价。所有费用都是 API 等价估算，不是 ChatGPT 订阅实际账单。
- 每个 Bot 最多保留最近 1,000 条；“全部已保存”不代表完整历史累计。缺字段、文字估算、读取失败都有提示；写入中的文件暂时不可读时保留上次成功读取的数据，不把失败显示成零。多 Bot 共用同一统计目录时去重。
- 新引擎区分程序存活与微信连接，显示待扫码、待确认、正在答题、登录过期、自动恢复等状态。
- 关闭窗口后管理器留在系统托盘。右键托盘可停止全部并退出；旧版运行的实例需要先接管才能由管理器停止。
- 勾选“登录 Windows 后启动”设置当前用户登录后的自启动；各 Bot 还需勾选“随管理器自动启动此 Bot”。未接管的旧版不由此自动拉起。

## 依赖与数据

程序内置 Node.js 和微信桥接依赖，无需另装 npm。仍需本机安装并登录 Codex；找不到时点击“选择 Codex”。把 EXE 复制到另一台电脑不会带走微信/Codex 登录信息。

程序文件、完整源码和技能快照在 `程序文件/engine-...`。管理列表在 `data/manager.json`；配置改动保留上一版本。新增 Bot 数据在 `data/bots/...`，原有 Bot 继续使用其原始目录。备份请连同数据目录一起备份，勿只备份 EXE。

## 从源码重建

完整源码内含 C# 界面、Node 控制器、TypeScript 微信/Codex 桥、测试和打包脚本。需要 Windows x64、.NET Framework 4.x C# 编译器、Node.js 24 和 npm。

1. 在源码目录安装 `package.json` 所列构建依赖。
2. 准备 `skills/gaokao-english` 技能目录（源码包内附快照）。
3. 运行 `Build.ps1 -NodePath <node.exe>`。
4. 输出位于 `release/微信英语Bot管理器.exe`。

`node --test tests/controller.test.mjs` 在临时数据中验证端口互斥、控制鉴权、异常恢复、停止与状态隔离，不连接真实微信或调用模型。

`微信英语Bot管理器-用量整合版.exe --self-test <新的测试目录>` 验证资源解包、独立端口、归档恢复、配置重载、用量计算、所有功能按钮图标、常规与最小窗口渲染，以及只清理本次启动实例的隔离测试。结果和预览图写入测试目录，示例用量不是真实账号数据。

`Build.ps1` 在编译之前运行 Windows PowerShell 5.1 的脚本解析、中文备份往返、精确匹配、备份失败/部分失败恢复等模拟回归测试。测试替换全部任务与进程查询/控制操作，不操作真实计划任务。控制器测试使用本机假 Bot，不连接真实微信或请求 Codex。

打包采用文件白名单，排除 `.env`、微信令牌、聊天记录、图片、日志以及复制留下的运行备份。运行程序本身不产生模型请求，学生题目触发 Codex 时才使用模型额度。
